# Koha Offline Library Tool

A lightweight, browser-based offline circulation tool for [Koha](https://koha-community.org/) designed to allow library staff to record checkout transactions when the Koha server or network connection is unavailable.

This version has been modified for use by the **Mansfield/Richland County Public Library (MRCPL)**.

The application runs entirely in a web browser and does not require a web server, database, installation, or active network connection. Circulation transactions are stored locally in the browser and can be exported as a Koha Offline Circulation (`.koc`) file for later processing in Koha.

## Features

* Offline item checkout
* Koha-compatible `.koc` file generation
* Browser-based local storage
* MRCPL item barcode validation
* Patron card entry and patron switching
* Due date entry
* Checkout receipt generation and printing
* Automatic timestamping of circulation transactions
* On-screen transaction log
* No external dependencies
* No Internet connection required
* Runs from a single HTML file

## MRCPL Barcode Validation

This version validates item barcodes before adding a checkout transaction.

Valid MRCPL item barcodes must follow the format:

```text
316570xxxxxxxx
```

where `xxxxxxxx` represents eight additional numeric digits.

A valid item barcode therefore:

* Contains exactly **14 digits**
* Begins with **316570**
* Contains only numeric characters

The validation is implemented with the following regular expression:

```javascript
/^316570\d{8}$/
```

If an invalid barcode is entered or scanned, the transaction is rejected and the user is notified.

## Requirements

The application requires only a modern web browser with JavaScript and browser local storage enabled.

No installation is required.

Compatible browsers should include current versions of:

* Google Chrome
* Microsoft Edge
* Mozilla Firefox

Because all application logic is contained in the HTML file, the tool can be stored locally on a circulation computer or other appropriate location and opened directly in the browser.

## Installation

1. Download `Koha Offline Circ.html`.
2. Save the file to the desired location on the circulation workstation.
3. Open the file using a supported web browser.
4. The Koha Offline Library Tool will open locally.

No web server is necessary.

## Using the Tool

### 1. Set the Due Date

Select the appropriate due date before beginning checkout.

### 2. Enter the Patron Card

Scan or enter the patron's library card number in the **Patron Card** field.

### 3. Scan Items

Scan each item into the **Barcode** field.

The application validates each item barcode before accepting the transaction.

Valid example:

```text
31657012345678
```

Invalid examples:

```text
3165701234
12345678901234
3165701234567A
```

Accepted transactions are added to the transaction log.

### 4. Change Patrons

Select **Change Patron Card** when beginning circulation for another patron.

The new patron card replaces the current patron and the receipt list is cleared.

Previously recorded `.koc` circulation data is retained.

### 5. Save

The **Save** button stores the current circulation data in the browser's local storage.

The application also periodically saves the transaction data automatically.

### 6. Print Receipt

Select **Print Receipt** to generate a printable receipt containing:

* Patron card number
* Transaction date/time
* Item barcodes
* Due dates

The receipt information is separate from the `.koc` transaction data.

### 7. Download the KOC File

Select:

**Download data (.koc)**

The application generates a timestamped `.koc` file containing the offline circulation transactions.

Example filename:

```text
kolt_2026-08-13_18-45.koc
```

The generated file can then be processed through Koha's Offline Circulation functionality.

## KOC Data

The application generates Koha Offline Circulation records using the general structure:

```text
date/time    issue    patron_barcode    item_barcode
```

The file begins with the header:

```text
Version=1.0    Generator=kolt    GeneratorVersion=0.1
```

A checkout transaction is generated in the form:

```text
YYYY-MM-DD HH:MM:SS    issue    PATRON_BARCODE    ITEM_BARCODE
```

Fields are separated by tab characters.

For additional information about the Koha offline circulation format, see the Koha Community documentation:

https://wiki.koha-community.org/wiki/Koha_offline_circulation_file_format

## Processing the KOC File in Koha

After normal Koha service has been restored:

1. Log in to the Koha staff interface.
2. Open **Circulation**.
3. Locate the option to upload an offline circulation (`.koc`) file.
4. Select the `.koc` file generated by this application.
5. Upload the file.
6. Add the transactions to the offline circulation queue.
7. Review the pending offline circulation actions.
8. Process the transactions according to your library's normal Koha procedures.

Staff should review offline transactions for errors or conflicts during processing.

## Local Data Storage

Circulation data is stored using the browser's `localStorage` feature.

The storage key used by the application is:

```javascript
kolt_data
```

This allows transaction data to survive normal browser refreshes or closing and reopening the HTML file in the same browser environment.

### Important

Browser local storage should not be treated as a permanent backup.

Before clearing data, staff should verify that the `.koc` file has been successfully downloaded and retained.

## Clearing Data

The **Clear** button removes locally stored circulation transaction data.

The application asks for confirmation before deleting the data.

After clearing, the transaction log is reset to the standard `.koc` header.

**Do not clear the application until the offline circulation file has been safely downloaded and retained.**

## Privacy and Security

The application operates locally and does not intentionally transmit patron or circulation information to an external server.

However, offline circulation data contains patron and item identifiers and should be treated as library circulation data.

Appropriate precautions should include:

* Use the tool only on authorized library computers.
* Protect generated `.koc` files according to library policy.
* Do not leave offline circulation files in publicly accessible locations.
* Process offline transactions promptly after Koha service is restored.
* Delete temporary circulation files when they are no longer required.
* Clear locally stored transaction data after confirming successful recovery and processing.

## Project Structure

The application is intentionally self-contained.

```text
Koha Offline Circ.html
```

The HTML file contains:

```text
HTML
├── User interface
├── Checkout controls
├── Results display
└── Receipt controls

CSS
└── Application styling

JavaScript
├── Application initialization
├── Checkout processing
├── Barcode validation
├── Date/time generation
├── Patron switching
├── Local storage
├── KOC generation
├── File download
├── Transaction display
└── Receipt printing
```

No external JavaScript libraries or CSS frameworks are required.

## Barcode Validation Code

The MRCPL-specific validation occurs before a checkout is written to the circulation log:

```javascript
const barcode = app.get("bar_ckout").value.trim();

if (!/^316570\d{8}$/.test(barcode)) {
  alert(
    "Invalid item barcode. Item barcodes must start with 316570 and be 14 digits long."
  );

  app.get("bar_ckout").value = "";
  app.get("bar_ckout").focus();
  return;
}
```

Libraries adapting this project should modify this expression to match their own barcode scheme.

## Limitations

Because this is an offline application, it cannot query the live Koha database.

It therefore cannot verify:

* Whether a patron exists
* Whether a patron is blocked
* Whether an item exists in Koha
* Current item status
* Current circulation status
* Holds
* Fines or fees
* Circulation rules
* Whether an item is already checked out
* Whether a transaction will produce a conflict when uploaded

Barcode validation confirms only that an item barcode matches the configured MRCPL barcode format.

Koha remains authoritative when the offline transactions are later processed.

## Known Deployment Considerations

Browser local storage is associated with the browser environment in which the application is opened.

Changing browsers, browser profiles, computers, or clearing browser data may make previously stored transaction information unavailable.

For that reason, the generated `.koc` file should be downloaded before clearing browser data or changing workstations.

## Development

The application uses standard HTML, CSS, and JavaScript.

No build environment is required.

To modify the application:

1. Make a backup of the current HTML file.
2. Open the file in a text or code editor.
3. Modify the HTML, CSS, or JavaScript.
4. Save the file.
5. Open or refresh the file in a browser.
6. Test checkout and `.koc` generation before production use.

## Testing Recommendations

Changes should be tested with non-production or test data before deployment.

At minimum, verify:

* Valid item barcode acceptance
* Invalid prefix rejection
* Short barcode rejection
* Long barcode rejection
* Non-numeric barcode rejection
* Patron switching
* Multiple item checkout
* Local data persistence
* `.koc` file download
* `.koc` formatting
* Receipt printing
* Data clearing
* Successful processing of a test `.koc` file in Koha
